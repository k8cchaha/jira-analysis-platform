# 專案回顧與趨勢

[回功能總覽](../README.md) · 唯一入口：`/analytics/projects` · 狀態：**部分實作（Sprint篩選可用，分析尚未開放）**

## 目的
整合原專案分析、趨勢分析與比較分析的產品入口，規劃讓使用者以專案為主體，在指定 Sprint 回顧 Jira 工作、追查跨 Sprint 趨勢，並在相同條件下討論差異。日曆日期區間篩選已搬至 [團隊分析](analytics-team.md)，不再與 Sprint 模式並列。

**目前可用的是專案／Sprint 條件選擇、URL 還原與驗證。** 分析區仍顯示 ComingSoon，沒有可用的分析引擎、圖表、計算或比較對象選取器。

## 解決的問題
預期降低分析範圍不清楚，以及回顧、趨勢與比較入口分散造成的口徑誤解。現在將 Sprint 回顧與日曆期間篩選分開，完成的是篩選條件與入口整理，不是分析結果。

## 可以找到的 Insight
**目前沒有分析數字、趨勢或比較圖表可供判斷。** 以下僅為未來可討論的問題，不是既有功能或交付承諾：

| 規劃問題 | 未來需具備的訊號 | 可能行動 |
| --- | --- | --- |
| 專案在指定 Sprint 的工作構成如何？ | 明確母體的工作量／點數摘要與可核對明細 | 回顧集中項目、缺值與範圍後再追查原票 |
| 不同 Sprint 的工作是否持續變化？ | 固定期間粒度、定義一致的跨期指標與資料品質資訊 | 區分短期波動與長期變化，核對指派／範圍變動 |
| 相同條件下的工作構成有哪些差異？ | 同一期間、對象類型、母體與計算條件的可對帳結果 | 先核對點數尺度、角色與範圍，再追查差異來源 |

指標、完成定義、可比較對象及歷史母體尚未定案。沒有移動平均、Velocity、趨勢線、異常偵測、預測或排行榜；不應從此頁推導改善、退步、因果或績效結論。

## 使用方式
- **Sprint-only**：只提供 Project、Team、複選 Sprints 與查詢，沒有區間模式 radio、日期欄位或日期快捷鍵。
- 專案單選且必選；未選之前 Team、Sprints 與查詢不可操作。專案／Team 共用既有元件及中央寬度，窄容器可換行並夾至可用寬度。
- Sprints 可複選該專案的完整本機設定清單（含歷史與未來，最新在前），沒有自動預選，至少一個有效 Sprint 才能查詢。
- Team 僅選整個團隊、不提供逐成員排除；留在本頁本次 local state，不寫入分析 URL、不是 server 授權邊界，也不是比較對象選取器。重新整理不保存 Team。
- Project、Sprints 選擇即時更新 URL；新網址只含 `project` 與重複 `sprint`，例如 `/analytics/projects?project=SUN&sprint=6823&sprint=7518`。更換專案清除舊專案 Sprint，保留本頁 Team 選擇；上一頁／下一頁從有效 URL 還原專案與 Sprint。
- 單一舊 `mode=sprints` 仍可還原 Sprint 條件，但新 URL 不帶 `mode`；其他模式不能在本頁啟用日期分析。
- URL 還原、重新整理與條件變更**不自動分析**。查詢按鈕只驗證／確認目前條件，顯示分析尚未開放的提示，不讀取分析資料。
- 未知參數、重複單值參數、無效 Project／Sprint、其他專案的 Sprint 與舊日期條件都會明確報錯；無效 URL 不會自動修正、退回預設範圍或啟用查詢。
- **舊日期網址不自動跳頁**：本頁顯示錯誤與手動「移至團隊分析」連結。完整有效的舊 `mode=dates`＋`project`／`from`／`to` 會在連結保留專案與日期，例如移至 `/analytics/story-points?project=SUN&from=2026-10-01&to=2026-10-31`；`mode` 不帶到新入口。未知／重複／混合條件、無效專案或日期等不合法舊網址只連到乾淨的 `/analytics/story-points`，不猜測或搬移部分範圍。須由使用者點選，抵達團隊分析也不自動分析。
- 原 `/analytics/trends`、`/analytics/comparison` 根路徑及已知子頁別名仍以 **307直接跳轉**至本頁。跳轉層保留所有 query 值（含未知、無效與重複值），抵達後才依 Sprint-only 契約驗證；帶舊日期條件的網址仍需上述手動搬移。未知子路徑不列為跳轉別名。

## 指標與判定規則
尚無分析母體、聚合公式、歷史重建或完成規則。不要套用工作量／Burn Down 的計算，或因有複選 Sprint 或整合比較入口便認為已查詢 Jira 或產生分析。

## Jira 資料依據
- **沒有專案回顧與趨勢的分析 JQL 或分析 REST request。** 不將共用但未接入的 analysis builders 當作本頁實作；篩選搬移不新增 Jira 資料管線或寫入。
- Project／Sprint 來自程式內設定，不使用 Jira Agile Sprint API；共用 Team 元件可能讀取 Jira 團隊成員 metadata，這不等於取得專案分析資料。
- 未使用分析結果欄位。未來實作仍應遵守 [Jira 技術參考](../jira-reference.md) 的集中 builder／授權契約。

## 限制與解讀注意事項
條件可選、URL 可還原、按鈕可啟用與舊入口可跳轉，都不代表分析引擎已完成；沒有可匯出、可跨期分析或可比較的結果。未來歷史回顧需處理範圍、欄位、父子關係與指派變動；不同點數尺度、工作母體、角色或出勤不能直接橫比。現有期間內的週分布請見 [工作量分析](analytics-workload.md)，其母體與公式不因此變更。
