# 功能頁文件模板

[回功能總覽](README.md)

此模板用於 `docs/features/`，複製後替換括號內容。規劃頁也保留相同章節，但「目前沒有實作」要直說，不填假查詢／假數據。

```markdown
# （功能頁名稱）

[回功能總覽](../README.md) · 路徑：（實際路由） · 狀態：（已實作／部分實作／規劃中／舊服務無頁面）

## 目的
幫助誰完成哪項判斷或工作？

## 解決的問題
沒有這個頁面時的具體困難；不要以未驗證成效作結論。

## 可以找到的 Insight
| 問題 | 訊號 | 可能行動 |
| --- | --- | --- |
| 使用者的判斷問題 | 頁面真正提供的數字／清單 | 可追查的下一步，不是系統自動行動 |

規劃問題須標為規劃，不能混入目前可用Insight。

## 使用方式
篩選、預設、查詢觸發、URL／本機狀態、圖表與明細、可讀／可寫操作。

## 指標與判定規則
母體、去重、分母、公式、空值／0、精度、日期／時區、排除條件、完成定義。

## Jira 資料依據
已接入的constant／builder名稱、示例完整JQL、REST method／path、欄位用途、站內資料流。
未實作則寫「沒有」，不要借用未接入的共用library。

## 限制與解讀注意事項
現值或歷史、fallback、資料與權限限制、已知明細對帳差異、不能直接推論的結論。

## 實作狀態與程式來源
實際page、client、service、API、聚合與權威定義的repository相對連結。
```

## 完成檢查
- 路由存在嗎？是在主導覽還是補充入口？不要從舊README推定存在。
- 有真實Jira I/O，還是靜態／mock／本機state／ComingSoon？
- 每個Insight的訊號在畫面真的存在嗎？目前不可用的問題是否明確標示？
- SP、Actual、0／缺值、完成日與母體是否清楚？跨頁差異是否保留？
- JQL範例是否對照權威builder輸出，並標示合成inputs？
- read資格與write資格是否分開？client篩選是否被誤寫成server授權？
- 來源連結與狀態總覽是否同步？不要抄程式過時註解而忽略真正行為。
- 不含credentials、token、真實accountId、私人email或真實業務資料。

遵守 [AGENTS.md](../AGENTS.md)，不因文件整理任意更改production query或write範圍。README及Markdown為權威文字；HTML／PDF若產生，從這些來源轉出並標版本。
